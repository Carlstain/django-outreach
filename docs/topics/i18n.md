# Internationalisation

- Message ids are English. A French catalogue ships in `src/outreach/locale/fr`. No other
  language is shipped.
- `USE_I18N` must be `True`, otherwise nothing is translated.
- `OUTREACH_LANGUAGE` (default `LANGUAGE_CODE`) picks the language per view with
  `translation.override`, so the rest of your site is unaffected. It applies to the Outreach
  admin site, its login page, the public unsubscribe pages and the rendering of each mail.
- No `LocaleMiddleware` is needed, and none is forced on the host project. The site renders its
  responses inside the override on purpose, since template rendering happens after a view returns.
- Variable labels use the message context `mail variable`, their examples `mail variable
  example`. Tag labels use `mail tag` and `mail tag example`.

## Translating your own tags

Rendering a mail runs inside the `OUTREACH_LANGUAGE` override, because tags such as `today` and
`greeting` are translated. A tag of your own can use `gettext` and `date_format` directly.

## Adding a language

Create `src/outreach/locale/<code>/LC_MESSAGES/django.po` by copying the French file and
translating it, then compile it:

```shell
pybabel compile -d src/outreach/locale -D django -l <code>
```

After editing the French `.po`, run `scripts/compile_messages.sh`. The `.mo` file is generated and
is never edited by hand. Only `fr` is checked in CI.
